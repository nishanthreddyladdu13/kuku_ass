# CineControl — React + FastAPI starter

A local-first scene-planning prototype based on the supplied Part A / Part B diagrams.

## Windows quick start

Prerequisites: Python 3.12 (with the Windows Python launcher), Node.js 22.12 or newer, and a modern browser. No Blender, GPU model downloads, ComfyUI, or FFmpeg required for the editor.

1. Extract the ZIP. Open PowerShell in the `cinecontrol-react-fastapi` folder.
2. Install dependencies and build the frontend:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-windows.ps1
```

3. Start the app:

```powershell
powershell -ExecutionPolicy Bypass -File .\start-windows.ps1
```

4. Open http://127.0.0.1:8000. API docs: http://127.0.0.1:8000/docs.
5. Choose an example, adjust objects and cameras, and export a reference pack. These examples are hand-authored, not generated by the text box.

The scripts use process-only PowerShell execution policy; they do not change machine policy. Close the server with Ctrl+C.

## Enable actual text-to-scene generation

Edit `backend/.env` locally (setup creates it from `.env.example`):

```dotenv
LLM_PROVIDER=gemini
LLM_MODEL=your_available_structured_output_model_id
LLM_API_KEY=your_key_here
LLM_BASE_URL=
IMAGE_MODEL=core
STABILITY_API_KEY=your_stability_key_here
```

Select a model ID actually available to your Google API account. No model is silently assumed. Restart FastAPI after editing. The provider uses the configured `LLM_MODEL` with Gemini's `generateContent` REST endpoint via HTTPX; no SDK installation is needed. A live response must satisfy the Pydantic JSON schema. Structured output is capped at 4096 tokens. One repair attempt is allowed. Gemini HTTP 503 responses receive at most three total provider requests per scene, including a repair request, with jittered exponential backoff; each request is bounded to 20 seconds and the full scene to 70 seconds. Logs record stage timings and request/schema sizes without logging prompts, API keys or request headers. New input generation returns an explicit error without configured access.

Alternatively, use a JSON-output-capable chat-completions provider:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_MODEL=your_model_id
LLM_API_KEY=your_key
LLM_BASE_URL=https://your-provider.example/v1
```

A ChatGPT subscription is not automatically an API credential. Never paste keys into the React code, screenshots, repository or submission. This local app is not authenticated: do not expose its generation endpoint publicly without adding authentication and quotas.

## Generate a scene image

The scene workspace can generate an image for the selected shot. `POST /api/scene-image` accepts the validated scene and shot ID; `POST /api/scene-image/upload` can additionally take a PNG/JPEG/WebP reference frame. Both use a server-side `STABILITY_API_KEY`; `IMAGE_MODEL` selects Stability's `core` or `ultra` text-to-image model. The image request is made once (no retries), bounded by a 120-second upstream timeout and a 135-second overall deadline. The response includes image MIME type and base64 data. Generated images are review drafts; the frontend displays them and includes them in the exported reference pack.

## Development: two terminals

Backend, from project root:

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Frontend, from project root in another terminal:

```powershell
cd frontend
npm.cmd run dev
```

Open http://localhost:5173. Vite proxies `/api` to FastAPI. Rebuild with `npm.cmd run build` to update the single-server app on port 8000.

## Implemented scope

One rectangular room; 1–4 principal characters; up to 20 objects and 4 shots. Supported kinds: character, table, chair, sofa, bed, counter, shelf, door, window, box. Round/rectangular tables; configurable dimensions and rotations; standing/seated proxies. The shared animation timeline supports deterministic object move/rotate/scale/appear/disappear tracks and per-shot camera pan/tilt/dolly/track/zoom tracks. Timeline tracks are validated for references, continuity, channel conflicts and room bounds. The player supports play, pause, restart, seek and playback speed; the Handoff tab uses the browser's native video controls for imported clips.

Character meshes are unrigged proxies: movement is linear blocking, not a walk/run cycle. Jump arcs, gestures, grasping, facial animation, orbit cameras, pathfinding and physics are not implemented and must be recorded as unsupported rather than claimed as animated.

Units: metres. Origin: room centre. +Y up. Object position: bottom centre. Rotation: degrees around Y; zero faces +Z. World left/right uses X. Door/window are solid visual panels on walls, not openings for navigation. The room has an open ceiling for overview inspection.

## Data flow

React text -> POST `/api/scene` -> server-side model -> Pydantic validation/one repair -> scene JSON -> frontend Zod validation -> Three.js timeline player -> user edits -> PNG/JSON/ZIP. A selected scene/shot can also go to POST `/api/scene-image` -> server-side Stability image model -> reviewed image preview/export.

- GET `/api/health`: configuration status (never keys).
- GET `/api/examples`: local sample scenes.
- GET `/api/schema`: exact backend JSON schema.
- POST `/api/validate`: validates imported/edited scene and returns warnings.
- POST `/api/scene`: actual model request, not an offline keyword router.

The generated raw responses and original prompts are stored under `backend/data/runs`. They can contain private scripts. Review them before sharing. They are ignored by git and excluded from this starter ZIP.

## Part B — manual handoff

Generate an appearance image for a selected shot or download the camera preview and action prompt to create one externally. Compare it with the preview, then generate a clip in a supported image-to-video service. Use the Handoff tab to review/import results, add notes and export them. Media/notes are temporary until export. Save each accepted and rejected attempt before changing scenes or shots.

No video service is connected. No model is guaranteed to accept the exported depth maps. Depth is a diagnostic reference: 8-bit linear camera-forward distance over 0.1–40m, white near and black far. Generated MP4s are external, not outputs of the app itself.

## Testing

```powershell
cd backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd ../frontend
npm.cmd test
npm.cmd run build
```

The included tests check three different scene structures, dynamic character counts, invalid IDs, missing credentials, error/repair limits, movement endpoints, explicit relationships, geometry variants, rendering, serialization and sampled depth. Model tests simulate provider responses. They do NOT establish unseen-text interpretation quality.

See `evidence/STATUS.md` for what was and was not verified. Windows scripts were reviewed but not executed on Windows here. Browser testing could not launch in the build environment because browser sockets were restricted.
